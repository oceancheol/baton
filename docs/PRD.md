# Baton (바통) PRD

현대자동차그룹 차량용 앱 개발 공모전 출품작. 작성 2026-11-14, v0.1.

## 1. 한 줄

주차장을 떠나는 차가 조작 없이 "곧 자리가 납니다"를 알리고, 가장 먼저 닿을 수 있는 차 한 대를 그 자리로 안내하는 Pleos Connect 차량용 앱.

## 3. 범위

### M1 — 11/15 접수 전 (가산점용 뼈대)
- 에뮬레이터에서 실행되는 앱. 화면 4종(나가는 차 / 들어오는 차 대기 / 우선 안내 / 주차 완료).
- 차량 신호 구독: Door 위치, Seat 착좌, Safety 경고등(주차 브레이크), Brake 페달.
- 출차 판정 상태기계: 주차 중 → 탑승 → 예고 → 출차 임박 → 비었음. 2분 무이동 취소.
- 상대 차는 앱 안의 모의 구현(같은 프로세스). 실제 서버 없음.
- SDK가 없는 환경(일반 에뮬레이터, 단위 시험)에서도 돌아가는 모의 신호 소스와 시연용 조작 패널.
- release APK, README.

### M2 — 12/2까지 (PT 시연)
- FusedLocation으로 주차장 진입·자리 이탈 판정, 도착 예상 시간.
- TextToSpeech 음성 안내(ON_DEVICE), NaviHelper로 인근 주차장 목적지 설정.
- 모의 서버 분리(상대 차 여러 대, 안내 순서 계산), 오판 비율 측정 화면.
- Virtual Console로 진행하는 시연 시나리오 고정.

### 설계 검토(11/14)에서 받아들인 것 — M1·M2에 반영
- 안내 불변 조건: 차 한 대와 예고 하나에는 유효한 안내가 하나뿐이다. 예고가 취소되면 안내도 바로 끝난다. 앞 차가 떠난 뒤 180초가 지난 자리는 안내하지 않는다.
- 실패 복귀 시 기다린 시간을 보존한다. 양보 기록은 다른 조건이 같을 때만 순서에 반영한다.
- 최소 신호 조합은 운전석 착좌 + 위치 이동. 둘을 읽지 못하면 자동 예고를 끈다.
- 위치 신뢰도가 낮으면 줄 대신 구역까지만 안내한다. 확률 수치는 화면에 쓰지 않는다.
- 예고가 없을 때 문구는 "관측된 출차 예고 없음".
- 측정: 예고부터 실제 이탈까지의 시간, 잘못 보낸 안내 비율, 안내 뒤 주차 성사율.
- 주차 뒤 복귀 시 현재 신호 상태를 다시 읽어 상태기계를 복원한다.
- 시연 구성(M2): 짐만 싣기(예고 없음) → 탑승 후 출발(한 대에만 안내) → 이탈·접근 + 실제 음성 → 주차 후 그 차가 다음 예고 차 → 예고 후 무이동 취소 → 대체 주차장 내비 연동. 화면 옆 관찰 패널에 SDK 입력·판정·안내 결과 표시. 모의 위치·상대 차·시간 배속은 화면에 명시.

### 범위 밖
- 기어·시동·차속 판독, 휴대폰 보조 앱, 실서버, 결제, 지하 주차면 단위 안내.

## 4. 기능 요구

### F1 출차 자동 예고
- 입력 신호와 판정 단계

| 단계 | 조건 | 상태 전이 |
|---|---|---|
| 1 | 주차 상태에서 운전석 문이 열렸다 닫힘 | PARKED → BOARDING |
| 2 | 운전석 착좌(벨트 체결이 읽히면 함께) | BOARDING → ANNOUNCING (예고 시작) |
| 3 | 주차 브레이크 경고등 꺼짐 또는 브레이크 페달 밟음 | ANNOUNCING → DEPARTING (안내 시작) |
| 4 | 위치가 주차 지점에서 일정 거리 이상 벗어남 | DEPARTING → VACATED |

- 예고를 시작한 시점(ANNOUNCING 진입)부터 120초 안에 VACATED에 이르지 못하면 PARKED로 되돌리고 예고와 진행 중인 안내를 함께 취소한다. 단계가 바뀌어도 120초를 다시 세지 않는다.
- 착좌가 풀리거나 문이 다시 열리고 60초 안에 닫히지 않으면 취소한다.
- "이번엔 예고 안 함"을 누르면 이번 주차 동안 예고하지 않는다.
- 각 신호는 지원 여부를 먼저 확인한다. 최소 조건은 운전석 착좌와 위치 이동이며, 둘 중 하나라도 읽지 못하면 자동 예고를 끄고 화면에 이유를 표시한다. 나머지 보조 신호(문, 벨트, 주차 브레이크 경고등, 페달)는 없으면 빼고 판정한다(대체 규칙은 6장).
- 신호 상태는 미수신 / 사용 가능 / 미지원 / 일시 불가를 구분한다. 구독을 시작할 때 현재 값을 먼저 읽어 상태를 복원하고, 이 초기값을 '변화'로 세지 않는다.

### F2 한 대에게만 우선 안내
- 예고 자리의 위치는 공개하지 않는다. 다른 차에는 구역별 `곧 날 자리 N · 대기 N대`만 보인다.
- 순서: 서행 기준 도착 예상 시간 − 대기 보정이 가장 작은 차. 그 값이 같을 때(1초 단위로 반올림해 비교)만 양보 기록이 많은 차가 먼저다.
- 안내 유효 시간 180초. 넘기면 다음 차로 넘긴다. 자리 자체도 앞 차가 떠난 시각부터 180초가 지나면 안내·집계에서 뺀다. 유효성은 타이머가 아니라 조회·보고 시점의 시각으로 판단한다.
- 안내와 예고에는 ID를 붙이고, 주차 보고는 현재 유효한 안내 ID와 일치할 때만 받는다.
- 안내받은 차가 자리 위치를 지나쳤는데 주차하지 않으면 다음 예고의 대기 순서로 되돌린다.
- 화면에 "보장이 아님"을 적는다.

### F3 화면과 음성 안내, 주차 위치 저장
- 큰 숫자 하나(남은 시간), 단순 경로, 음성.
- 주행 중에는 터치 입력을 받지 않는다. 구역은 자동 추천, 변경은 정차 중에만. (M1 현재: "이번엔 예고 안 함"만 움직이는 중에 꺼진다. 시연 패널을 포함한 나머지 터치 차단은 아직 구현하지 않았다.)
- 주차가 끝나면 구역·줄, 걸린 시간을 저장한다.

### F4 인근 주차장으로 분산 (M2)
- 예고 자리가 없고 대기가 많으면 정차 중에 묻고, 수락하면 NaviHelper로 목적지를 설정한다.

## 6. 기술

- Kotlin, Jetpack Compose, minSdk 28, compileSdk/targetSdk 35, JDK 17 이상.
- SDK 저장소: `https://nexus-playground.pleos.ai/repository/maven-releases/`
  - 현재 연결한 SDK(M1): `ai.pleos.playground:Vehicle:2.3.2` 하나.
  - M2 예정(아직 의존성에 없음): `FusedLocation:1.1.3`, `NaviHelper:3.0.5`, `TextToSpeech:3.3.1`.
- 에뮬레이터: Pleos Connect v2.1.0, API 34, Automotive AVD, Cold boot, RAM 4GB. Virtual Console은 `adb forward tcp:8088 tcp:8088` 후 `http://127.0.0.1:8088/`.
- 퍼미션(조회용만)
  - 현재 선언한 것(M1): `pleos.car.permission.CAR_DOORS`, `CAR_SEATS`, `CAR_SAFETY`, `CAR_DRIVE`, `PRIVATE_CAR_SAFETY`. 주차 브레이크 경고등 조회에 `PRIVATE_CAR_SAFETY`가 필요하다(SDK 2.3.2에서 확인). SDK가 스스로 `ai.pleos.playground.service.vehicle.VEHICLE_BINDING`을 더한다. 에뮬레이터에서 이 Pleos 권한들의 보호 수준은 normal이다. AndroidX가 넣는 앱 내부용 `DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION`은 signature다.
  - M2 예정(아직 선언하지 않음): `FUSED_LOCATION`, `NAVI_ROUTE`, `NAVI_ROUTE_SEARCH`, `TTS_SERVICE`.

### 구조

```
core/         순수 Kotlin (Android·SDK 의존 없음)
  signal/     SignalSource 인터페이스, 신호 모델
  departure/  DepartureStateMachine (시계 주입, 단위 시험 대상)
  match/      안내 순서 계산, MockPeerService(상대 차 모의)
app/
  signal/     PleosSignalSource(SDK), FakeSignalSource(모의)
  ui/         Compose 화면 4종 + 시연 패널
```

- 상태기계와 안내 순서 계산은 Android·SDK에 의존하지 않는 순수 Kotlin으로 두고 단위 시험을 붙인다.
- SDK 호출은 `PleosSignalSource` 한 곳에만 둔다. SDK 초기화가 실패하면 `FakeSignalSource`로 내려가고 화면에 "모의 신호"라고 표시한다.
- 실제 차량 신호: 관측 시각·순번·주차 세대를 콜백에 들어온 순간에 찍는다. 현재 값 조회는 한 번에 하나만 돌고, 구독을 먼저 등록해 조회 중의 변경을 모아 두었다가 기준값 뒤에 내보낸다. 10초마다 현재 값을 다시 물어 하나도 읽지 못하면 차량 신호를 일시 불가로 바꿔 예고를 취소하고, 다시 읽히면 현재 값으로 복원한다.
- 새 주차의 기준값 복원은 처음 연결할 때의 복원과 구분한다: 새 주차에서는 계속 앉아 있다는 이유로 예고하지 않고 문 여닫힘(또는 하차 후 재착좌)을 기다린다.
- 에뮬레이터에서만 확인한 해석(착좌 값 뒤집기, 벨트 제외, "경고등 목록에 항목 없음 = 꺼짐")은 Pleos Connect 에뮬레이터(`Build.FINGERPRINT`가 `Pleos/crp_avd`로 시작)에서만 쓴다. 그 밖의 환경에서는 착좌를 쓰지 않아 자동 예고가 꺼지고, 주차 브레이크 경고등은 빼고 페달·이동으로 판정하며, 벨트는 SDK 지원 확인 결과를 따른다. 실차에서는 확인하지 않았다.

### 확인이 필요한 것과 대체 규칙

| 항목 | 상태 (2026-11-14, Pleos Connect v2.1.0 에뮬레이터 + Vehicle SDK 2.3.2) | 안 될 때 |
|---|---|---|
| 운전석 문 열림·닫힘 | 확인. `Door.getCurrentDoorPosition` / `registerDoorPosition`(`DoorArea(ROW_1_LEFT)`, 값은 정수: 0 닫힘) | 문 없이 착좌부터 판정 |
| 운전석 착좌 | 확인. `Seat.getCurrentSeatOccupancy` / `registerSeatOccupancy`(`SeatArea(ROW_1_LEFT)`). SDK 값이 Virtual Console과 반대로 온다(Occupied → false). 이 에뮬레이터에서만 뒤집어 읽는다. 실차에서 방향 재확인 필요(그 전까지 실차에서는 착좌를 쓰지 않는다) | 최소 신호라 대체 없음(자동 예고 끔) |
| 브레이크 페달 | 확인. `Brake.getCurrentBrakePedalStatus` / `registerBrakePedalStatus` | 이동 시작으로 3단계 판정 |
| 주차 브레이크(Safety Telltale) | 확인. `Safety.getTelltalesInfo` / `registerTelltales`의 `TelltaleType.PARKING_BRAKE`(전자식은 `ELECTRONIC_PARKING_BRAKE`). 켜진 경고등만 목록에 온다(이 에뮬레이터에서 확인. 그래서 "항목 없음 = 꺼짐"은 이 에뮬레이터에서만 쓴다). `PRIVATE_CAR_SAFETY` 권한이 필요하다(`CAR_SAFETY`만으로는 거부). 실차·심사에서 이 권한이 허용되는지는 미확인 | 브레이크 페달 + 이동 시작으로 3단계 판정 |
| 문 잠금 영역 조회 | 쓰지 않음(미확인) | 문 열림·닫힘만 사용 |
| 안전벨트 체결 시험 | 조회·구독 호출은 됨. Virtual Console에 벨트 조작이 없어 값 변화는 미확인 | 착좌만 사용(이 에뮬레이터에서는 시연 설정으로 벨트를 판정에서 뺀다. 그 밖의 환경은 SDK 지원 확인 결과를 따른다) |
| 에뮬레이터 위치 주입 | 미확인. FusedLocation은 연결하지 않음 | 앱 안의 모의 위치 |
| API 파라미터·반환 타입 | SDK aar의 시그니처로 확인(위 네 신호와 안전벨트) | — |
| Virtual Console 값 변경 방법 | 확인. 콘솔 화면 또는 HTTP `PUT /vehicle/body`, `/vehicle/seat`, `/vehicle/controls`, `/vehicle/telltales/simulator` | — |
| 맥(Apple Silicon)에서 Pleos 에뮬레이터 구동 | 확인(arm64 이미지, 창 없이 구동해 앱 실행·신호 수신) | 일반 Automotive AVD + 모의 신호로 시연 |
| 실제 차량 | 미확인 | — |

## 7. 성공 기준

M1
1. `./gradlew test` 통과: 상태기계의 정상 흐름, 2분 취소, 문 재개방 취소, 신호 미지원 대체 규칙, 안내 순서 계산.
2. `./gradlew assembleRelease`로 APK 생성, 에뮬레이터에 설치·실행.
3. 에뮬레이터에서 신호를 바꾸면(Virtual Console 또는 시연 패널) 화면 상태가 PARKED → ANNOUNCING → DEPARTING → VACATED로 바뀐다. 화면 캡처로 확인.
4. README와 `apk/` 폴더가 공모전 요건을 채운다.
5. 소스·README·커밋 기록에 개인 실명·연락처·키가 없다.

M2는 M1 검수 뒤 다시 정한다.
